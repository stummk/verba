# Verba — руководство пользователя

Verba превращает аудиозаписи в редактируемый текст — полностью локально,
с опциональной ИИ-очисткой/переводом, экспортом в PDF, семантическим поиском
и публичным API транскрипции.

## Установка и запуск {#install}

**Готовые пакеты** (страница релизов проекта):

- **Windows:** `Verba-Setup-….exe` — двойной щелчок, мастер установки, ярлык
  в меню «Пуск». Verba устанавливает обновление сама (см. «Обновление»);
  запуск нового установщика поверх текущей установки по-прежнему работает.
  Данные хранятся отдельно для каждого пользователя и переживают обновления.
- **Linux (десктоп):** `Verba-….AppImage` — сделать исполняемым и запустить.
- **Linux (сервер):** распаковать `verba-server-….zip` и выполнить
  `sudo ./deploy/install.sh` — настраивает службу systemd и автозапуск;
  шаблоны для nginx/Caddy прилагаются. Для существующей установки та же
  команда автоматически обновляет Verba, сохраняя данные и рабочие области.

**Из исходного кода:**

- **Windows:** двойной щелчок по `start.bat`
- **Linux:** `./start.sh` в папке проекта
- **Сервер:** `./start.sh --server --port 8710` — доступен по IP/домену,
  в том числе за обратным прокси (пробросьте WebSocket `/ws`)

При первом запуске базовые компоненты устанавливаются автоматически;
приложение открывается в браузере по адресу `http://127.0.0.1:8710`.

**Адрес при запуске.** Каждый запуск выводит в консоль, что именно слушает
Verba — в серверном режиме вместе со всеми IP-адресами компьютера, чтобы было
понятно, куда подключаться с другого устройства:

```
------------------------------------------------------
Verba 0.1.0 - server mode
  listening on   http://0.0.0.0:8710  (all interfaces)
  local          http://127.0.0.1:8710
  network        http://192.168.1.50:8710
  data directory /opt/verba/data
  stop with Ctrl+C
------------------------------------------------------
```

Как **служба** (systemd) тот же блок попадает в журнал: `systemctl status
verba` показывает его в конце, `journalctl -u verba` — с самого начала. Кроме
того, адрес есть в первой строке журнала приложения (`data/logs/`), то есть и
для службы, работающей неделями. Если порт занят, Verba прямо об этом сообщает
и не запускается — без аварийной трассировки.

В режиме рабочего стола кнопка **✕** в правом верхнем углу закрывает вкладку
Verba и останавливает локальный процесс. Он останавливается и без этой кнопки:
как только закрыта последняя вкладка Verba (или весь браузер), сервер ждёт
несколько секунд на случай перезагрузки страницы и затем завершается сам. В
режиме сервера Verba продолжает работать, пока не остановлена служба.

Verba — это **PWA**: браузер может «установить» приложение (значок в адресной
строке или «Добавить на главный экран»), после чего оно ощущается как
самостоятельная программа. Интерфейс загружается и без соединения; как только
сервер снова доступен, работа продолжается автоматически.

## Обновление {#updates}

Раз в сутки Verba проверяет, есть ли более новая версия, и сообщает об этом:
короткое уведомление, пока приложение открыто, и подсказка на начальной
странице. Установить обновление может только администратор.

В разделе **«Настройки» → «Система»** сверху показана текущая версия, а рядом
две круглые кнопки: круговая стрелка сразу ищет новую версию, не дожидаясь
ежедневной проверки, а стрелка вниз устанавливает её. Если более новая версия
есть, эта кнопка активна и выделена, а её подсказка называет версию
(«Обновить до 0.1.2»); если текущая версия самая новая, кнопка неактивна.
Строка под кнопками говорит словами, как дела сейчас.

По нажатию Verba загружает пакет, соответствующий этой установке, и
устанавливает его. Все шаги построчно попадают в журнал обновления под
кнопкой: загрузка, проверка, установка, перезапуск. Журнал виден только во
время установки — после перезапуска в строке сверху стоит новый номер версии,
и это и есть ответ.

- **Windows:** установщик работает без мастера. Windows один раз запросит
  разрешение — это единственное действие, которое остаётся за вами. Затем
  Verba закрывается, установщик заменяет файлы и снова запускает Verba.
- **Linux (десктоп):** запущенный файл AppImage заменяется новым, после чего
  приложение перезапускается.
- **Linux (сервер):** Verba обновляет зависимости, заменяет файлы приложения
  и перезапускает службу.
- **Установка из исходного кода:** здесь обновляет `git pull`. Кнопка остаётся
  неактивной и указывает причину.

Старая версия при этом удаляется — она больше не нужна, как только работает
новая. Всё важное к ней и не относится: база данных, журналы, настройки,
рабочие области и загруженные модели лежат вне файлов программы и остаются
нетронутыми. Если Verba на сервере запущена не как служба, журнал в конце
сообщает, что нужен перезапуск.

Проверка запрашивает у GitHub последний выпуск. Если это не нужно, отключите
**«Автоматически искать новые версии»** в «Настройках» → «Система»: тогда ни
один запрос не покидает компьютер, а обновления выполняются через страницу
релизов проекта.

### Системные пакеты сервера

Если Verba работает на Linux-сервере, под строкой версии появляется вторая
строка: **Linux-сервер** с одной круглой кнопкой, которая обновляет системные
пакеты машины — `apt update` и `apt upgrade`, то есть именно то, что иначе
набирают по SSH. В Windows и на десктопе этой строки нет.

По нажатию выполняются оба шага, а ниже показывается журнал сервера: каждая
строка, которую выводит apt, по мере её появления. Журнал не сохраняется — это
запись одного этого запуска. Саму Verba это не затрагивает, и сервер никогда
не перезагружается сам: если пакету нужен перезапуск, журнал сообщает об этом
в конце.

Ниже находится флажок **«Полное обновление (dist-upgrade и autoremove)»**. С
ним вместо `apt upgrade` выполняется `apt dist-upgrade` — он устанавливает и
пакеты с изменившимися зависимостями и может при этом удалять пакеты, — а
затем `apt autoremove`, который убирает то, что больше не нужно. Это
основательный вариант, и выбирать его стоит осознанно: без флажка набор
пакетов сервера остаётся неизменным. Выбор действует только для этого запуска
и не сохраняется; подсказка кнопки говорит, какой из двух вариантов она
запускает.

Для установки нужны права: служба работает как root или может использовать
`sudo` без пароля. Без этого кнопка остаётся неактивной, а строка под ней
называет причину.

## Первичная настройка {#first-run}

Первичная настройка проходит в шесть шагов и охватывает всё, что нужно Verba:

1. **Установка компонентов** — Verba проверяет систему (Python, ffmpeg, GPU,
   ИИ-компоненты) и автоматически устанавливает недостающее. Прогресс виден в
   реальном времени: полоса показывает всю установку, а каждый компонент
   получает галочку сразу после установки и проверки — включая необязательный
   семантический поиск, который поэтому можно доустановить в любой момент.
   Пока идёт установка,
   кнопки **Далее**, **Пропустить шаг** и **Настроить позже** заблокированы —
   они снова становятся доступны, как только установка завершится или
   завершится с ошибкой.
2. **Хранилище** — каталог данных (база данных и журналы) и каталог рабочих
   папок, где Verba хранит папки транскриптов (раздел «Транскрипты»).
   Изменённый здесь каталог данных начнёт использоваться со следующего
   запуска — см. «Настройки».
3. **Расшифровка** — модель по умолчанию, каталог моделей, устройство и язык
   записей (раздел «Модели Whisper»).
4. **Языковая модель** — необязательно (при выборе «Локально (llama.cpp)»
   llama.cpp можно установить сразу здесь, а журнал построчно показывает
   каждый шаг): выкл, локально или
   OpenAI-совместимый эндпоинт (раздел «Настройка языковой модели (LLM)»).
5. **Поиск** — модель эмбеддингов для семантического поиска (раздел «Поиск»).
6. **Доступ** — при необходимости создать учётную запись администратора и тем
   самым включить управление пользователями (раздел «Пользователи и
   видимость»). Если шаг пропустить, Verba остаётся без защиты — это имеет
   смысл только при локальной работе на этом компьютере.

Любой шаг можно пропустить кнопкой **Пропустить шаг** — тогда действует
значение по умолчанию, которое всегда можно изменить в настройках. Кнопка
**Настроить позже** полностью выходит из настройки — напоминание о
незавершённой настройке при этом остаётся. Пока идёт первичная настройка,
вкладки навигации скрыты; они появляются, когда вы завершаете или покидаете
её. Настройку можно открыть позже в разделе **Настройки**.

Если установка не удалась, уже готовые компоненты сохраняются; перезапуск
Verba и повторная попытка удаляют только действительно повреждённый пакет.

## Транскрипты {#transcripts}

У каждого транскрипта есть собственная **рабочая папка** на диске: `audio/`
(импортированные копии), `transcripts/` (JSON-транскрипты) и `exports/`. Все
они лежат в **каталоге рабочих папок** из настроек (по умолчанию: `workspaces`
рядом с приложением или в каталоге данных установки). Там уместны
**абсолютные пути**, в том числе на сетевых и съёмных дисках
(`M:\Транскрипты`); `~` и `%USERPROFILE%` раскрываются, а путь в кавычках
(как его копирует проводник Windows) принимается. Относительный путь сразу
превращается в абсолютный и так же показывается в настройках.

Если позже изменить каталог, **все существующие папки транскриптов
переезжают вместе с ним** — фоновая задача переносит их (на том же диске за
секунды, между дисками столько же, сколько копирование) и обновляет ссылки в
базе данных. Если в целевом каталоге уже есть папка с таким же именем, смена
отклоняется и ничего не переносится: сначала переименуйте или перенесите
чужую папку сами.

- Новый транскрипт: кнопка **+** (справа внизу). Если имя не введено,
  используется сегодняшняя дата (`ггггммдд`).
- При создании можно выбрать **тип транскрипта** (раздел «Типы транскриптов»)
  — он определяет, как
  ИИ-обработка работает с текстом. Без типа получается чистый,
  неформатированный текст.
- При удалении транскрипта можно по желанию удалить и рабочую папку.

При импорте Verba автоматически извлекает **метаданные**: название и дату из
MP3-тегов и из имён файлов по схеме `ГГГГММДД_Название` (например,
`20240817_Название.mp3`).

## Типы транскриптов {#types}

В комплекте шесть стандартных типов: **Song** (песня), **Interview**
(интервью/диалог), **Speech** (речь), **Protocol** (протокол с резюме и списком задач), **Poem**
(стихотворение) и **Role play** (ролевая игра).

У каждого типа есть **структура** и **два промпта**, между которыми в
редакторе переключает выпадающий список.

**Структура** определяет, из чего строится экспорт в PDF и как он
структурируется без ИИ:

- **Абзацы** — сплошной текст из обработанного текста (по умолчанию).
- **Строфы** — переносы строк сохраняются (песня, стихотворение).
- **Диалог** — строится из сегментов с говорящими, а не из объединённого
  текста; каждая реплика с именем говорящего (интервью).
- **Сценарий** — как диалог, но имена персонажей заглавными буквами
  (ролевая игра, пьеса).

Благодаря этому и собственный тип может использовать сегменты с говорящими —
раньше это было жёстко привязано к стандартным типам.

Рядом есть **«Не разрывать разделы между страницами»**. При экспорте всего
транскрипта один файл иначе следует за другим на той же странице, и раздел
разрывается там, где заканчивается страница. С этой опцией раздел файла
начинается с новой страницы, как только он уже не помещается на текущую —
считается всё, что к нему относится: колонтитул, текст и переводы, которые
идут в том же PDF после оригинала. То есть если B помещается лишь наполовину
или B помещается, а его перевод — уже нет, B начинается сверху следующей
страницы. Разделы, которые помещаются, не сдвигаются: несколько коротких
записей по-прежнему стоят на одной странице. А раздел длиннее страницы не
получает пустой страницы перед собой — он всё равно нигде не помещается
целиком и переносится, как раньше. Опция относится к типу, то есть действует
только для использующих его транскриптов, и у всех стандартных типов
отключена.

Два промпта:

- **Промпт очистки** — говорит ИИ, как обрабатывать сам транскрипт (абзацы,
  говорящие, слова-заполнители, строфы …).
- **Промпт формата вывода** — говорит ИИ, как обработанный текст делится на
  блоки для **экспорта в PDF**: абзацы, заголовки, строфы, реплики диалога,
  списки (например, решения и задачи) и разделители. У стандартных типов он
  подобран заранее: для песни — блоки строф, для протокола — списки решений и
  задач.

Если промпт формата вывода пуст, применяется стандартный; он показан в поле
как подсказка, а «Вставить стандартный» возвращает его для правки. **Новый
тип** уже предзаполнен им, остаётся только подправить. Если ИИ не может
выполнить инструкцию, экспорт возвращается к структурированию по правилам —
PDF создаётся всегда.

Типы управляются в отдельной вкладке **Типы** (главная навигация): список
для выбора и рядом редактор имени, структуры и промптов — на смартфоне
поочерёдно как список и детальный вид. Кнопка **+** создаёт новый тип;
стандартные типы тоже можно изменять и удалять. «Восстановить стандартные
типы» возвращает удалённые или изменённые стандартные типы (оба промпта).

## Импорт аудио {#import}

Карточка действий в транскрипте делит процесс на три вкладки:
**1. Импорт аудио → 2. Транскрибировать и обработать → 3. Экспорт.** Нажатие
на вкладку показывает действия именно этого шага; когда файлы уже есть,
предвыбран шаг 2.

Три равноценных способа:

1. **Загрузка** — выбор файлов кнопкой «Загрузить файлы»
2. **Импорт с сервера** — просмотр папок компьютера/сервера; при импорте
   папки берутся все аудиофайлы внутри (включая вложенные)
3. **Перетаскивание** — перетащите файлы или целые папки в область с пунктирной
   рамкой на шаге «Импорт аудио»; только она принимает файлы

Поддерживаемые форматы: mp3, wav, m4a, flac, ogg, opus, aac, wma, webm, mp4.
Импорт всегда копирует — исходные файлы остаются нетронутыми.

При загрузке (в том числе перетаскиванием) карточка прогресса показывает, какой
файл передаётся сейчас («Файл 2 из 7»), насколько продвинулась вся выборка и
когда сервер сохраняет файл.

## Расшифровка {#transcribe}

- **Один файл:** значок микрофона в строке файла (у готовых файлов вместо
  него значок повтора для нового запуска)
- **Всё сразу:** «Расшифровать все» в шаге 2 карточки действий
- **Дополнительно (раскрывается):** модель Whisper и язык записи только для
  этого запуска — сохранённые настройки не меняются
- Прогресс отображается по каждому файлу; запущенные задачи можно отменить
- Совет: явное указание языка записи (вместо автоопределения) заметно
  улучшает результат

**Где виден прогресс.** Каждый шаг сообщает, с каким файлом он работает и
насколько продвинулся:

- **В строке файла** (вид транскрипта): полоса и текст, например
  `lied.mp3: 01:23` при расшифровке (проценты — позиция в записи),
  `Bereinigung 2/5` и `Übersetzung 1/3` при ИИ-обработке,
  `Warteschlange: Position 3` при ожидании. «Расшифровать все» и «ИИ-обработка
  (все)» создают задачу **на каждый файл**, поэтому у каждой строки своя
  полоса.
- **В верхней панели**: сводка, которая сохраняется при переходе между
  разделами — `KI-Aufbereitung — lied.mp3: Bereinigung 2/5 · 40 %`. Если
  параллельно идут две задачи (расшифровка и обработка), показаны обе,
  остальные как `+2 ещё`.
- **В списке транскриптов**: отметка `3 в работе` у транскрипта, пока там
  что-то выполняется.
- **Отдельной карточкой**: задачи, не относящиеся к одному файлу — экспорт
  всего транскрипта в PDF, перестройка поискового индекса («Настройки →
  Поиск»), перенос рабочих папок («Настройки → Хранилище»).
- **В редакторе**: отдельные полосы для «повторной расшифровки фрагмента» и
  для ИИ-обработки открытого файла.

**Очередь:** все задачи проходят через одну центральную очередь, чтобы
оборудование никогда не перегружалось — даже когда работают несколько человек
одновременно. Ожидающие файлы показывают свою позицию; небольшие задачи
(повторная расшифровка участка, монтаж аудио) пропускаются вперёд, а порядок
остаётся честным для каждого пользователя.

## ИИ-обработка (очистка и перевод) {#ai}

Как только языковая модель настроена (раздел «Настройка языковой модели
(LLM)»), у расшифрованных файлов
появляется **значок искры (ИИ-обработка)**, а в шаге 2 карточки действий —
кнопка **ИИ-обработка (все)**:

- **Очистка** убирает слова-паразиты и фальстарты, исправляет пунктуацию и
  явные ослышки — тип транскрипта учитывается как контекст («откровение»
  правится лишь минимально, «протокол» получает резюме и список задач)
- **Перевод** переносит очищенный текст (или сырой транскрипт) практически
  на любой язык — доступны все ~100 языков, которые знает Whisper
- Длинные записи автоматически делятся на части по границам сегментов
  (с перекрытием), чтобы даже локальные модели с небольшим контекстом
  работали корректно — двухчасовая запись это примерно 17 запросов, результаты
  которых Verba снова соединяет
- **Ничего не сокращается.** Verba не задаёт модели верхнюю границу длины
  ответа: она отвечает настолько, насколько хватает её контекстного окна. Если
  ответ всё же обрывается посреди текста, Verba делит часть пополам и
  спрашивает снова, вместо того чтобы сохранить укороченный транскрипт. И
  только если не проходит даже короткая часть, шаг завершается ошибкой
- Результаты появляются во вкладках ИИ-диалога и в редакторе, а также
  сохраняются как Markdown-файлы в рабочей папке в `transcripts/`

**Что выполняется сейчас.** Диалог закрывается при запуске — дальше ход работы
виден в строке файла и назван по шагу (например, «ИИ-обработка · Очистка 2/5»).
Завершённые шаги строка помечает как **очищено** и **переведено**, поэтому видно,
прошёл ли файл ИИ-обработку. Повторный щелчок не ставит тот же шаг в очередь
дважды; для переводов учитывается язык — второй целевой язык получает
собственный запуск, а перевод стартует и тогда, когда очистка того же файла
ещё выполняется. Если шаг завершился ошибкой, причина показывается сообщением и остаётся
в строке файла — пустой результат никогда не сохраняется, иначе и любой PDF из
него был бы пустым. Значки в строке файла идут в порядке работы: расшифровка →
ИИ-обработка → редактор (проверка) → PDF.

**Полная автоматика:** **«Обрабатывать автоматически»** в окне транскрипта уже
включено для каждого нового проекта (по желанию с целевым языком); один щелчок
выключает это снова. Тогда после каждой завершённой
расшифровки очистка — и, если задан язык, перевод — запускаются сами, без
единого лишнего щелчка. Ручной запуск отдельных шагов остаётся доступным в
любой момент.

**Планирование:** если LLM работает на другой машине (внешний API),
транскрипция и ИИ-обработка идут параллельно. Если модель работает локально
на той же системе, Verba действует поэтапно: сначала все расшифровки, затем —
после однократной смены модели — вся ИИ-обработка. Whisper и LLM делят память,
не мешая друг другу.

## Редактор и таймлайн {#editor}

Действия показаны значками с подсказками (при наведении видно описание).
Значок документа («Открыть в редакторе») у расшифрованного файла открывает
редактор — **рабочую область** для
аудио, транскрипта и ИИ-текстов:

- **Волновая форма** с воспроизведением/паузой; щелчок по метке времени
  сегмента переносит аудио туда; при воспроизведении активный сегмент
  подсвечивается
- **Три области** под таймлайном: *сегменты* (исходный транскрипт), *очищено*
  и *перевод* — все редактируются напрямую с автосохранением. На больших
  экранах области стоят **рядом**, как в настольном приложении, и включаются/
  выключаются по отдельности; на смартфоне те же вкладки переключают виды —
  весь набор функций сохраняется.
- **Какой текст в итоге учитывается**, написано подсказкой над областями: пока
  очистки нет, перевод и PDF создаются прямо из сегментов. Как только очистка
  появилась, она становится основой для обоих — более поздние изменения в
  сегментах подействуют только после повторного создания очистки. Исключение —
  макеты с говорящими (*диалог*, *сценарий*): там PDF всегда строится из
  сегментов вместе с говорящими, а очистка служит только основой перевода.
- **Сегменты и ИИ-текст прокручиваются вместе** и имеют одинаковую высоту,
  поэтому фрагмент можно читать рядом с его очищенной или переведённой версией.
  Соответствие пропорциональное — очищенный текст сплошной, а не по блоку на
  сегмент.
- **Волновая форма остаётся вверху при прокрутке** (начиная с ширины планшета),
  чтобы воспроизведение и выделение всегда были под рукой.
- **ИИ-тексты прямо из редактора**: если текста нет, его создают «Создать
  очистку» или «Создать перевод» (с выбором языка); если он уже есть,
  **«Создать заново»** создаёт его повторно и заменяет. Ход выполнения и ошибки
  показаны под областями — если шаг завершился с ошибкой, причина остаётся на
  месте, а не выглядит так, будто ничего не произошло.
- В выборе языка перевода языки сгруппированы в **«Уже переведено»** и **«Ещё не
  переведено»**; переключение сразу показывает соответствующую версию.
- **Смена файла и экспорт без обходных путей**: список вверху переключает на
  другой файл того же транскрипта, а рядом значок PDF запускает **экспорт**
  прямо из редактора.
- **Текст и говорящий** редактируются прямо в строках сегментов — изменения
  сохраняются автоматически (индикатор «Сохранено»), **Отменить** пошагово
  возвращает последние изменения
- **Выделение** перетаскиванием по волновой форме, затем:
  - **Расшифровать выделение заново** — заново распознаётся только этот
    участок, заменяя ровно затронутые сегменты
  - **Обрезать до выделения / Удалить выделение** — монтаж через ffmpeg;
    результат появляется как *новый* файл транскрипта, оригинал сохраняется

## Модели Whisper {#whisper}

В разделе **Настройки → Транскрипция** **один список** показывает все модели
с их статусом: установленные помечены как «установлено» и удаляются прямо
там, отсутствующие скачиваются одним щелчком. Практическое правило: `small` —
хороший старт; `large-v3` даёт лучшее качество, но требует заметно больше
ресурсов. Собственные модели CTranslate2 можно класть папками в каталог
моделей (подпапки распознаются) — они появляются в том же списке.

**Подходит ли модель этому компьютеру?** Рядом со статусом каждая строка несёт
оценку для **этой** системы — Whisper всегда работает локально, поэтому считаются
собственные ОЗУ и собственная видеопамять:

- **подходит** (зелёный) — памяти достаточно, модель работает свободно
- **с ограничениями** (оранжевый) — работает, но с оговоркой: либо память почти
  заполнена, либо модель не входит в видеопамять и поэтому идёт на процессоре
  (заметно медленнее)
- **слишком большая** (красный) — памяти этой системы не хватает; подсказка
  сразу называет самую большую модель, которая здесь поместится

При наведении на оценку виден весь текст с цифрами (например, «нужно ок. 2,3 ГБ,
свободно 3,9 ГБ VRAM»). Та же рекомендация для компьютера в целом стоит над
списком, а в помощнике первичной настройки (шаг 3) — прямо под полем модели.

**Если памяти всё же не хватает.** Verba не падает:

- Модель, которая не помещается никуда, отклоняется **до** загрузки — задача
  завершается с сообщением, приложение продолжает работать.
- Если она не входит в видеопамять, попытка на GPU пропускается и загрузка идёт
  сразу на процессоре.
- Если видеопамять заполняется уже в ходе расшифровки, Verba переходит на
  процессор и пишет об этом в строке прогресса.
- Если заполнено ОЗУ, задача завершается сообщением с указанием свободных и
  требуемых гигабайт.

**Собственный каталог моделей** (например, готовая коллекция в
`M:\Modelle\whisper`) указывается в **Настройки → Транскрипция** и действует
сразу, без перезапуска: Verba читает каталог с диска при каждом запросе.

- Находится любая вложенная папка с файлом `model.bin` — она появляется в
  списке под именем своей папки.
- Если папка названа точно как стандартная модель (`large-v3`), эта модель
  считается **установленной** и не скачивается повторно. То же касается кэша
  HuggingFace (`models--Systran--faster-whisper-…`), если загрузка завершена.
- Если имя папки другое (`faster-whisper-large-v3`, `eigene/my-finetune`), она
  появляется как отдельная модель и доступна для выбора — просто без отметки
  «стандартная».
- Папки без `model.bin` и прерванные загрузки игнорируются.
- Не существующий путь создаётся. Если он на сетевом диске, который сейчас не
  подключён, список остаётся пустым.

## Настройка языковой модели (LLM) {#llm}

В разделе **Настройки → ИИ-обработка (LLM)** переключатель выбирает ровно
**один** путь — видны только его поля:

- **Выкл** — очистка/перевод отключены, всё остальное работает как обычно
- **Локально (llama.cpp)** — совсем без внешних сервисов: Verba показывает
  обнаруженное оборудование (ОЗУ, GPU/VRAM) с рекомендацией модели; один щелчок
  устанавливает llama.cpp, другой скачивает выбранную модель. Локальный
  LLM-сервер запускается автоматически по мере надобности.
- **OpenAI-совместимый эндпоинт** — базовый URL, API-ключ и название модели
  (работает с OpenAI, Ollama, LM Studio, vLLM и др.); «Проверить соединение»
  проверяет эндпоинт и показывает доступные модели.

**Установка llama.cpp.** Кнопка есть в «Настройки → ИИ» и в первичной
настройке на шаге **Языковая модель**, как только выбрано «Локально
(llama.cpp)». И там, и там показывается один и тот же **журнал установки**:
распознанная система, выбранный выпуск и пакет, загрузка, распаковка,
доустановленные системные пакеты и проверка версии — построчно, пока это
происходит. Переключение раздела или перезагрузка страницы журнал не теряет:
он приходит с сервера.

**Какой llama.cpp устанавливается?** Verba берёт официальный выпуск,
подходящий системе: в Windows с GPU NVIDIA — сборку CUDA вместе со средой
выполнения CUDA, иначе сборку для CPU; в Linux и macOS — сборку для CPU, так
как пакета CUDA для Linux llama.cpp не выпускает.

После распаковки Verba один раз пробно запускает `llama-server`. Если при этом
не хватает системной библиотеки — на скромном Linux-сервере обычно `libgomp1`,
`libstdc++6` или `libssl3`, — **Verba сама устанавливает нужный пакет** (apt,
dnf/yum, zypper, pacman или apk) и пробует снова; это работает, пока служба
запущена от root или `sudo` разрешён без пароля. Если не получается,
недоустановленное удаляется, а сообщение называет точную команду
`apt install …`. Если сам дистрибутив слишком стар (выпуску нужны glibc 2.34 и
libstdc++ из GCC 11, то есть Debian 12, Ubuntu 22.04 или новее), сообщение
скажет и это — вместо срыва позже, на первом шаге ИИ. Если загрузка обрывается
— модели весят несколько ГБ, — Verba продолжает её с места обрыва.

**Эндпоинт на собственном компьютере.** Если базовый URL указывает на
`localhost` или `127.0.0.1` (обычно так работают Ollama и LM Studio), под полем
появляется **оценка**: сколько памяти здесь свободно сейчас и какой размер модели
с этим реалистичен. Именно оценка, а не приговор, как у собственных моделей: какую
модель загружает этот сервер и использует ли он GPU, решает он сам — Verba им не
управляет. Для адреса в сети или в облаке там не появляется ничего, потому что это
чужое оборудование.

**Какие локальные модели?** Verba содержит проверенный список многоязычных
instruct-моделей, упорядоченный по требованиям к оборудованию:

| Модель | Загрузка | Нужно минимум |
| --- | --- | --- |
| Qwen3 1.7B (Q8) | ок. 2,1 ГБ | 4 ГБ ОЗУ/VRAM |
| Qwen3 4B (Q4_K_M) | ок. 2,6 ГБ | 6 ГБ ОЗУ/VRAM |
| Gemma 3 4B (Q4_K_M) | ок. 2,4 ГБ | 6 ГБ ОЗУ/VRAM |
| Qwen3 8B (Q4_K_M) | ок. 5,2 ГБ | 10 ГБ VRAM / 20 ГБ ОЗУ |
| Gemma 3 12B (Q4_K_M) | ок. 7,0 ГБ | 14 ГБ VRAM / 28 ГБ ОЗУ |

**Звёздочка** отмечает рекомендацию для вашего компьютера: Verba смотрит на
VRAM (или половину ОЗУ без GPU) и предлагает самую большую подходящую модель
линейки Qwen3. Кроме того, **каждая** строка несёт ту же оценку, что и модели
Whisper (подходит / с ограничениями / слишком большая) — она относится только к
локальным моделям: OpenAI-совместимый эндпоинт работает на чужом оборудовании и
не оценивается. Модель, не входящая в видеопамять, остаётся в ОЗУ вместо того
чтобы уронить сервер при запуске; если она не помещается никуда, сервер вообще
не запускается и сообщает причину. При этом ничего не решается автоматически — модель вы
скачиваете сами и в любой момент можете выбрать другую; в поле **локальная
модель** видно, какую использует сервер.

**Модели с reasoning.** «Думающие» модели (Qwen3, DeepSeek-R1 и другие) ставят
свои размышления перед ответом — Verba их отрезает. Если модель выдала только
размышления или его бюджет токенов оборвал ответ до его начала, шаг завершается
именно с этой причиной, а не пустым текстом. Поэтому в LM Studio и подобных
лучше отключить режим размышлений или выбрать модель без reasoning. Сообщения
об ошибках эндпоинта (например, «model not loaded» или превышение длины
контекста) показываются дословно; если сервер загружает модель только при первом
запросе (так делает LM Studio), этот запрос может занять заметно больше времени,
чем последующие.

**Свои модели и свой каталог.** Поле **Каталог GGUF** задаёт папку с моделями
(например `F:\Models\llm`). Каждый файл `.gguf` в ней появляется в выборе и
**загружается прямо оттуда** — ничего не копируется и не скачивается заново.
Так же можно использовать модель, которой в списке нет: положите файл в папку,
выберите её в поле **локальная модель** — готово.

### Reasoning (режим размышления)

Некоторые языковые модели «думают» перед ответом — это видно по блокам
`<think>` или просто по тому, что ответа приходится долго ждать. Для Verba это
ничего не даёт: очистка, перевод и структурирование PDF — это преобразования с
чёткой инструкцией, а не задачи, над которыми нужно размышлять. Стоит это
вдвойне — времени и того бюджета токенов, который нужен самому ответу. Именно
отсюда берётся сообщение «модель израсходовала бюджет токенов до начала
ответа».

В разделе «Настройки → ИИ-обработка» для этого есть пункт **Reasoning**:

- **Выкл** (по умолчанию) — Verba прямо просит модель не размышлять. Заметно
  быстрее и это самая надёжная настройка.
- **Мало** — небольшое размышление остаётся разрешённым. Имеет смысл, если
  ответы ИИ в поиске и справке для вас важнее скорости обработки.
- **На усмотрение модели** — Verba не вмешивается (поведение до появления этой
  настройки).

Настройка действует везде: обработка, структурирование PDF, ответы ИИ в поиске
и вопросы по справке. Технически Verba отправляет `reasoning_effort` и — для
шаблонов, которые смотрят только туда — `chat_template_kwargs`. Эндпоинты,
которым эти поля неизвестны (например, сам OpenAI API), один раз их отклоняют;
Verba это запоминает и больше их не отправляет. Модели без режима размышления
всё равно их игнорируют.

## Экспорт в PDF {#pdf}

Расшифрованные файлы можно экспортировать в PDF — через значок PDF в строке
файла или кнопкой **Экспорт в PDF (все)** в шаге 3 карточки действий для
всего транскрипта.
В диалоге выбирается версия текста: оригинал (очищенный текст, иначе
сырой транскрипт) или готовый перевод.

Для переводов есть **два способа**, они выбираются в диалоге сразу под
«оригинал»:

- **По одной версии на PDF** — выбирается оригинал или конкретный язык. Язык
  добавляется в имя файла (`pesnya.pdf`, `pesnya.en.pdf`, `pesnya.ru.pdf`), и
  все версии лежат рядом в папке `exports/`.
- **«Оригинал + все переводы (один PDF)»** — оригинал и каждый сохранённый
  перевод попадают в **один** документ, друг под другом, разделённые
  центрированной строкой `---`. Файл называется `pesnya.all.pdf` и поэтому не
  перезаписывает отдельные экспорты. В сводном экспорте это работает для
  каждого файла: шапка и оригинал, затем `---` и переводы, затем следующий
  файл.

Добавленные версии **не повторяют шапку** — она была бы одинаковой, ведь
заголовок, дополнение и место/дата это метаданные файла и не переводятся.
Поэтому шапка отмечает новый файл, а `---` — смену языка. Если выбрать
отдельный язык, для которого перевода ещё нет, задача завершится с сообщением
об ошибке, а не молча экспортирует оригинал; в объединённом режиме просто
добавляются имеющиеся переводы.

Экспорт работает в два этапа: с настроенным LLM ИИ структурирует текст
по типу транскрипта (строфы, роли говорящих, протокол с резюме и
списком задач); без него структура создаётся по правилам — экспорт
работает всегда. Макет зависит от типа: например, невидимые
разделители и дополнительные пробелы или сценарный
макет для ролевой игры. Без типа получается простой текстовый PDF.

Основной текст выводится **по ширине** (выключка в блок). Переносы строк из
транскрипта при этом превращаются в пробелы между словами, чтобы абзац не
рвался посреди предложения — только строфы сохраняют свои строки. Если
языковая модель вернёт ответ, который вообще не построен на транскрипте
(например, просьбу прислать текст), он отбрасывается, и экспорт выполняется
по правилам. Если в транскрипте нет текста вовсе — например, запись без
речи, — задача завершится с сообщением об ошибке вместо PDF, в котором есть
только шапка.

В редакторе в разделе **Шапка PDF** для каждого файла можно задать заголовок,
дополнение и поле для места/даты. Строка шапки выглядит так:
`Заголовок (дополнение)` слева и место/дата справа — дополнение в скобках
стоит сразу после заголовка, через один пробел. Название и дата записи
подставляются автоматически. Пустые поля не оставляют следа: ни пустых скобок,
ни шапки вообще, если пусты все три поля.
Правое поле — **свободный текст**, в нём можно указать и место, например
`Мюнхен, 28.01.1933`. Дата в виде `ГГГГ-ММ-ДД` выводится при экспорте как
`ДД.ММ.ГГГГ` — в том числе внутри текста; всё остальное остаётся без
изменений.
Имена файлов могут иметь формат `дата_язык-файла_язык-перевода_название_дополнение`;
это автоматически заполняет язык, необязательный язык перевода и поля шапки.

**Экспорт в PDF (все)** создаёт общий PDF: каждый файл идёт как свой
раздел, отделённый только отступом — без оглавления и без
дополнительных заголовков. Готовые PDF появляются в карточке
**Экспорты (PDF)** для скачивания или удаления; в рабочей папке
они лежат в `exports/`.

## Поиск {#search}

Вкладка **Поиск** ищет сразу по всем транскриптам — семантически
(важен смысл; немецкие вопросы находят и английское, и русское
содержимое) и по полному тексту (имена собственные и редкие слова
совпадают точно). В разделе **Фильтры** поиск можно ограничить
транскриптом, типом, языком, говорящим и периодом.

**Список результатов.** Каждый файл стоит в списке ровно один раз,
под ним — все его совпадения в порядке времени, каждое со своей
отметкой времени: клик открывает редактор именно в этом месте, аудио
начинается там. Из отрывка показаны только сами совпадения: одна—три
строки вокруг каждого, искомые слова в них выделены цветом, всё
остальное опущено знаком «…». Если очистить поле поиска, список
исчезает вместе с вопросом.

**Поиск идёт и по заголовку.** Имя, дата и дополнительное примечание
стоят в заголовке файла, а не в произнесённом тексте — поэтому Verba
ищет и там: название, три поля заголовка, дата записи и имя файла.
Такое совпадение отмечено словом **Заголовок** и стоит выше текстовых
мест того же файла. Ищется буквально и сразу по всем словам запроса,
чтобы «Мейер 2024» нашёл именно этот файл, а не каждый, где где-то
встречается 2024; дату можно писать и в немецком виде («12.05.2024»).

С настроенным LLM кнопка **«Ответ ИИ»** стоит прямо рядом с
**Искать** и создаёт ответ, где каждое утверждение подкреплено
нумерованными источниками. В списке источников — только номер,
транскрипт, файл и место (сам отрывок стоит в ответе выше); он
кликабелен, как и результат. ИИ отвечает только по найденным
отрывкам — если их нет, он честно говорит об этом, а не гадает.

Новые расшифровки и правки сегментов индексируются автоматически;
удалённые файлы сразу исчезают из индекса. В разделе **Настройки →
Поиск** — статус индекса, модель эмбеддингов и кнопка ручной
перестройки. Компоненты поиска устанавливает настройка системы (группа
«Семантический поиск»). Пока их нет, кнопка **Начать настройку** в шаге 1
остаётся доступной, даже если всё остальное уже установлено.

**Модель эмбеддингов.** Доступен фиксированный список проверенных моделей —
все многоязычные (запросы на немецком находят английское и русское
содержимое) и пригодные для CPU:

| Модель | Размер | Языки | Характер |
| --- | --- | --- | --- |
| MiniLM multilingual (по умолчанию) | ок. 0,5 ГБ | 50 | быстро |
| Multilingual E5 small | ок. 0,5 ГБ | 100 | сбалансированно, точнее |
| mpnet multilingual | ок. 1,0 ГБ | 50 | тщательно, медленнее |
| BGE-M3 | ок. 2,3 ГБ | 100 | лучшее качество, заметно медленнее |

**Подходит ли модель этому компьютеру?** Как и у моделей Whisper, каждая запись
несёт оценку для этой системы (подходит / с ограничениями / слишком большая), а
под списком стоит весь текст с цифрами. Считается только **ОЗУ** — поиск всегда
считает на процессоре, видеопамять здесь не участвует. Если выбранная модель не
помещается, сообщение называет подходящую; а модель, которая не помещается,
отклоняется до загрузки, вместо того чтобы уронить индексацию на середине.

**BGE-M3** стоит выбирать, когда качество важнее скорости: это единственная
модель списка, у которой заметны и загрузка (ок. 2,3 ГБ), и время работы на
CPU, а её 1024 измерения увеличивают и размер индекса. На слабых машинах или
при очень большом числе транскриптов лучше остаться на модели по умолчанию.

Выбранная модель скачивается автоматически при первом использовании — для
этого один раз нужен интернет, дальше поиск работает полностью офлайн. Куда
именно, задаёт **Каталог моделей (эмбеддинги)** (по умолчанию
`<данные>/models/embeddings`). Если модель уже там, она **загружается оттуда,
а не скачивается снова** — распознаются и обычная папка (`bge-m3/`,
`BAAI_bge-m3/`), и перенесённый кеш HuggingFace
(`models--BAAI--bge-m3/snapshots/…`). В списке такие модели помечены «уже на
диске». Смена модели делает все сохранённые векторы
недействительными и поэтому автоматически запускает полную переиндексацию.
Если в статусе написано, что индекс построен другой моделью, достаточно
нажать **Перестроить индекс**.

## Настройки {#settings}

Настройки разбиты на разделы: на смартфоне — как в нативном приложении —
сначала показывается список разделов; касание открывает раздел как отдельную
страницу («Все настройки» возвращает назад). На настольных экранах список
разделов расположен сбоку от выбранного раздела.

- **Интерфейс:** язык (немецкий, английский, русский), документация —
  руководство показывается разделами со значками, каждый раздел
  раскрывается и закрывается. Если настроена языковая модель, над ним
  появляется **Вопрос по справке**: введите вопрос, и ИИ ответит
  исключительно по этому руководству. Ответ показывается с форматированием
  (абзацы, списки, код), как и само руководство. Каждый вопрос начинается
  заново (это не чат), а под ответом указано, на каких разделах он основан. Verba
  отправляет модели только подходящие к вопросу разделы; если и это не
  вмещается в её контекст, выборка автоматически уменьшается вместо
  сообщения об ошибке. Без языковой модели поля ввода нет.
- **Транскрипция:** модель по умолчанию, каталог моделей, устройство
  (GPU/CPU), точность вычислений, язык записей — включая управление моделями
  Whisper (скачивание/удаление) в том же разделе
- **ИИ-обработка (LLM):** выкл / локально / эндпоинт, каталог GGUF (раздел
  «Настройка языковой модели (LLM)»)
- **Хранилище и журналы:** каталог данных, каталог рабочих папок, порт
  сервера, уровень и срок хранения журналов (старые журналы удаляются
  автоматически). **Каталог данных** содержит базу данных и журналы — то,
  что должно попадать в резервную копию; путь на резервируемый диск и есть
  цель этой настройки. Настройки, загруженный ffmpeg и каталоги моделей
  остаются рядом с программой, потому что их всегда можно получить заново.
  Новый путь сохраняется как любая другая настройка, но сам перенос
  происходит при **следующем запуске**: база данных и файлы журналов открыты
  во время работы, и вытащить их из-под приложения нельзя. До этого под полем
  указано, куда состоится перенос, на начальной странице остаётся напоминание,
  а всё продолжает работать на прежнем месте. Папки транскриптов, лежащие по
  умолчанию внутри каталога данных, переезжают вместе с ним.
- **Размер базы данных:** при удалении транскрипта SQLite освобождает
  страницы, но не уменьшает файл — место используется при следующей записи.
  Когда свободного места накопится достаточно, Verba уплотняет базу сама:
  фоновым шагом «Уплотнение базы данных» после удаления и при следующем
  запуске. Небольшие остатки остаются, потому что полная перезапись файла
  ради них не окупается.
- **Поиск:** статус индекса, модель эмбеддингов (список выбора), каталог
  моделей, перестройка индекса
- **API:** ключи для публичного API транскрипции (раздел «Публичный API»)
- **Моя учётная запись:** смена собственного пароля, удаление собственной
  учётной записи и — для администратора — вход в управление пользователями
  (раздел «Пользователи и видимость»)
- **Система:** сведения о компьютере, на котором работает Verba —
  процессор (модель и ядра), оперативная память (свободно/всего),
  видеокарта с VRAM, статус ffmpeg — и версия приложения

## Пользователи и видимость {#security}

По умолчанию Verba работает **без защиты**: любой, кто откроет адрес, видит
всё и может всё. Для локальной работы на собственном компьютере это как раз
то, что нужно. Как только Verba работает на сервере или с ней работают
несколько человек, включите **управление пользователями**.

### Включение

При первичной настройке на шаге **Доступ** либо позже в любой момент в
разделе «Настройки → Моя учётная запись → **Открыть управление
пользователями**». Там вы создаёте учётную запись администратора; с этого
момента приложение защищено и доступно только после входа.

При включении ничего не теряется: все существующие расшифровки остаются без
изменений, остаются **общедоступными** — то есть видимыми всем авторизованным
пользователям — и закрепляются за первым администратором как за владельцем. Он
может затем передать их другим или изменить их видимость.

Если пропустить этот шаг, учётная запись не создаётся и Verba остаётся
открытой. Приложение прямо об этом предупреждает.

### Роли

- **Администратор:** управляет пользователями, настройками, моделями Whisper и
  языковыми моделями, типами расшифровок, поисковым индексом и API-ключами.
  Видит и редактирует любую расшифровку.
- **Пользователь:** работает со своими расшифровками и с теми, к которым ему
  дали доступ, ищет по ним и экспортирует их. В настройках ему остаются язык
  интерфейса, документация и собственная учётная запись.

Первый пользователь всегда администратор. **Последнюю** учётную запись
администратора нельзя ни удалить, ни понизить до обычного пользователя — иначе
не осталось бы никого, кто мог бы управлять пользователями и настройками.

### Создание учётных записей

Самостоятельная регистрация не предусмотрена: учётные записи создаёт
администратор в разделе «Настройки → Управление пользователями», со стартовым
паролем. При первом входе пользователь обязан задать собственный пароль — до
этого он дальше не пройдёт. То же самое повторяется, если администратор
сбрасывает пароль.

### Видимость каждой расшифровки

У каждой расшифровки одна из трёх видимостей. Она показана цветной меткой на
карточке расшифровки и меняется через значок замка:

- **Личная** — только владелец и администраторы
- **С доступом** — дополнительно явно выбранные люди
- **Общедоступная** — все авторизованные пользователи

**Кто видит расшифровку, тот может её также редактировать и удалять.**
Единственное исключение — сама видимость и список доступа: их меняют только
владелец и администраторы. Иначе коллега мог бы сделать общедоступную
расшифровку личной и закрыть доступ всем остальным.

Какую видимость получают новые расшифровки, задаёт администратор в разделе
«Управление пользователями → **Видимость по умолчанию**»; при создании можно
выбрать другую.

Видимость действует везде, а не только в обзоре: поиск находит только то, что
вам разрешено видеть, строка состояния не называет чужие имена файлов, а
файлы, сегменты и PDF-экспорты чужой личной расшифровки недоступны.

### Собственная учётная запись

В разделе «Настройки → **Моя учётная запись**» вы меняете пароль (при этом все
остальные устройства выходят из системы) или удаляете свою учётную запись.

При удалении учётной записи действует правило:

- **Личные** расшифровки удаляются вместе с аудиофайлами — они принадлежали
  только этому человеку.
- **Предоставленные и общедоступные** расшифровки сохраняются и переходят к
  самому давнему администратору. Это рабочий материал других людей, он не
  должен исчезать у них из-под рук.

То же происходит, когда администратор удаляет чужую учётную запись. Перед
удалением приложение называет количество затронутых расшифровок.

### Что ещё меняется

- **Публичный API** (`/v1`) при включённом управлении пользователями всегда
  требует API-ключ — иначе вход можно было бы обойти этим путём.
- Вход выполняется через сессионную cookie. Пароли хранятся в виде scrypt-хеша,
  сессии — только в виде контрольной суммы; в открытом виде в базе данных нет
  ни того, ни другого.
- **Обратный прокси с терминацией TLS** — это обычная схема, и она работает:
  Verba берёт схему браузера из `X-Forwarded-Proto` и по ней помечает cookie
  как `Secure` — соединение от прокси до Verba может оставаться обычным HTTP.
  Заголовок принимается только с `127.0.0.1`; если прокси работает на другой
  машине, запускайте Verba с `FORWARDED_ALLOW_IPS=<IP прокси>` либо задайте
  в настройках `auth.cookie_secure` значение `always`.

### Отключение — и включение обратно

В разделе «Управление пользователями → **Отключить управление
пользователями**». После этого Verba снова открыта для всех, кто откроет
адрес. Что при этом происходит:

- Все активные сеансы немедленно завершаются.
- Учётные записи сохраняются вместе с паролями и ролями.
- Владельцы, настройки видимости и списки доступа остаются в базе данных —
  они просто перестают применяться. Личная расшифровка снова доступна всем,
  но продолжает храниться как личная.
- Публичный API (`/v1`) возвращается к прежнему правилу: открыт, пока не
  создан ни один API-ключ.

Та же кнопка включает всё обратно — тогда она называется **Снова включить
управление пользователями** и ничего не спрашивает: вторая учётная запись
администратора не создаётся, все входят со своими прежними паролями, а
владельцы и настройки видимости снова действуют как раньше. У расшифровок,
созданных за это время, нет владельца; они переходят к самому давнему
администратору и остаются общедоступными, поэтому никого не блокируют.

## Публичный API {#api}

Verba предоставляет OpenAI-совместимый API транскрипции, чтобы внешние
программы могли расшифровывать аудиофайлы — скрипты, другие серверы или всё,
что работает с OpenAI SDK.

- **Конечная точка:** `POST /v1/audio/transcriptions` (multipart, формат OpenAI)
- **Форматы ответа** через `response_format`: `json` (по умолчанию), `text`,
  `srt`, `vtt` и `verbose_json` (с сегментами и временными метками)
- **Язык:** необязательно через `language` (ISO-код, например `ru`); иначе
  определяется автоматически
- **Модель:** `model=whisper-1` (или без параметра) использует модель Whisper,
  выбранную в настройках; конкретное имя вроде `model=small` выбирает другую
  модель для этого запроса
- **Обработка:** `model=whisper-1+cleanup` возвращает текст, очищенный
  ИИ-моделью (требуется настроенный LLM). `project_type=<ключ>` (например,
  `interview`) дополнительно очищает с промптом этого типа транскрипта. В
  `srt`/`vtt`/`verbose_json` сегменты остаются сырыми сегментами Whisper —
  очищается только текст.
- Каждый запрос проходит через ту же справедливую очередь, что и приложение,
  и отвечает, как только транскрипция готова.

**Ключи API:** Ключи создаются и удаляются в настройках в разделе «API».
**Название** обязательно — только по нему потом можно узнать ключ, поэтому
кнопка создания остаётся неактивной, пока поле пустое. Как
только существует хотя бы один ключ, конечная точка требует
`Authorization: Bearer <ключ>`; без ключей API открыт — это предназначено
только для строго локального использования. Каждый ключ показывается в
открытом виде ровно один раз; после этого видно только его начало.

Пример с curl:

```bash
curl -X POST http://localhost:8710/v1/audio/transcriptions \
  -H "Authorization: Bearer vb-ВАШКЛЮЧ" \
  -F "file=@запись.mp3" \
  -F "language=ru" \
  -F "response_format=srt"
```

Пример с OpenAI Python SDK:

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8710/v1", api_key="vb-ВАШКЛЮЧ")
with open("запись.mp3", "rb") as audio:
    result = client.audio.transcriptions.create(model="whisper-1", file=audio)
print(result.text)
```
